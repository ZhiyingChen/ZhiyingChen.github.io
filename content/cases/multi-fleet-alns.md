### 🧩 项目背景

在大型园区、后勤保障单位或国防工业中，常配备多类型作业车辆以执行不同等级的运输与服务任务。这些车辆需按时轮转执行任务，同时满足维修、安全、工时等现实约束。

本项目基于实际后勤运维需求，构建了一个<strong>多车种、有限维修周期、小时级任务需求</strong>的最小车辆数优化模型。通过将经典的“菱形错峰轮转算法”封装为子模块，并引入启发式的“大自然领域搜索（ALNS）”策略，成功提升模型泛化能力与求解效率。

## 📋 问题描述

车站有A种类型的车，每种类型的车数量为Bi ,i=1,2...A；

每种车到目的地执行任务的流程分为：装货，去往目的地，在目的地执行任务，返回车站，卸货。

每项工作所需时间见约束条件。

核心业务需求是在轮转好车执行任务的班次，用最少的车，满足任务要求。

````text
约束条件：

目的地要求同时有P（P为整数）辆车同时执行任务。

每种车装货时间ni,  i=1...A

每种车去往目的地时间ri,  i=1...A

每种车执行任务的时间si,   i=1...A

每种车返回目的地时间r’i,  i=1...A

每种车的卸货时间mi，i=1...A

每种车的最大连续运转周期Ui,  i=1...A；指车（ri+si+r’i）*累计出动架次 >=Ui时，需要维修保障

每种车维修保障时长Di，i=1...A

目的地执行任务的总时间跨度T
````

🎯 目标：<strong>制定轮转排班方案，用最少的车满足每小时任务需求，并符合车辆维修、出勤等约束</strong>

## 🔧 参数定义（按车种 i，i = 1,...,A）

| <strong>参数</strong> | <strong>含义</strong> |
| --- | --- |
| Bᵢ | 第 <em>i</em> 类车辆总数 |
| nᵢ | 装货时间 |
| rᵢ | 去往目的地时间 |
| sᵢ | 执行任务时间 |
| rᵢ&#x27; | 返回时间 |
| mᵢ | 卸货时间 |

| P | 每小时同时需要执行任务的车辆数 |

### 🧠 算法设计

#### 🔹 1. “菱形算法”子模块（错峰轮换）

> 该算法用于生成单车型 在保证服务区有同时有N辆车服务的时候 最小车辆使用策略，确保维修期错峰、任务持续不中断

核心机制：

- 控制新车与前一辆车之间的出发时间差（gap），以使维修高峰不重叠；

- 形成一个在时间轴上呈“菱形错峰”的出勤图谱；

- 被封装为 <code>car_type.get_car_num4specified_serve(...)</code> 等方法，在主框架中调用。

参考之前的 [汽车轮转与维修调度优化模型（1）单车种、维修错峰、最小车辆数](/cases/single-fleet/)

#### 🔹 2. ALNS（Adaptive Large Neighborhood Search）

> 作为主优化框架，用于在多个车种组合中选择最优分配方案

#### ✨ 核心模块：

- <strong>解的表示</strong>：字典记录每个车型同时进行服务的数量，{&#x27;车型A&#x27;: 1, &#x27;车型A&#x27;:2} →

    - 每个车若固定被分配服务的数量，则可调用 <strong>菱形算法 </strong>模块来计算最小使用的车辆数。

- <strong>解初始化</strong>：在不超过每个车型的车辆数量情况下，随机分配其服务的数量，生成基础可行解；

- <strong>摧毁算子</strong>：

    - 清空某一车种的服务数量；

    - 从某车种中随机减去一部分服务数量；

- <strong>修复算子</strong>：

    - 顺序补充空缺；

    - 随机填补空缺；

- <strong>自适应权重调整</strong>：根据算子成功率更新权重（轮盘赌选取）

#### 🔁 模拟退火调控：

- 初始温度 T = 100，末温 T = 10；

- 指数降温策略，鼓励早期探索，后期收敛；

- 保留当前最优解及各车种最小使用量、排班表。
